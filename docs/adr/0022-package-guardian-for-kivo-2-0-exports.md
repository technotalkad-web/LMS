## Decision

### A. The engine digest (ADR 0005 step 4, read as the owner's D1 (b); KIVO ADR 0013 Decision 7)

1. **Definition, version `v1`, frozen.** The digest is `sha256:` followed by the lower-case hex of SHA-256 over the UTF-8 encoding of `engineDigestInput(html)`, where `html` is the launch file `index.html` of the 2.0 zip decoded as UTF-8 (the editor hashes the string it zips; from G1 every text entry is written as the UTF-8 bytes of that string, KIVO ADR 0013's Addition on ED-24, the character-safe export fix the owner included on 2026-11-11 in the words "P-9 yes. Please include the character-safe export fix in KIVO 2.0 and proceed with the next development phase", so the stored bytes are that encoding). `engineDigestInput` removes exactly two ranges and inserts nothing:
   - Range 1, the licence body: every character strictly after the end of the begin anchor `<!-- KIVO-LICENCE-BEGIN -->` and strictly before the start of the end anchor `<!-- KIVO-LICENCE-END -->`. The newline after the begin anchor, the `<!--` and `-->` wrapper lines and the newline before the end anchor are inside the range and go; both anchors stay.
   - Range 2, the config body: every character strictly after the end of the opening tag `<script type="application/json" id="kivo-course-config" data-kivo="COURSE_CONFIG">` and strictly before the start of the first `</script>` that follows it. The newline after the tag and the newline before the closing tag are inside the range and go; the opening tag and the closing tag stay. The body cannot contain `</script`, because the 2.0 writer writes every `<` as `\u003c`.
   - The begin anchor, the end anchor and the opening tag must each occur exactly once in the whole text; the end anchor must follow the begin anchor; a `</script>` must follow the opening tag; range 1 must end before range 2 begins. Any other count or order gives no digest, and the function reports which anchor failed and how many times it was found.
   - No whitespace or line-ending normalisation of any kind (the A.1 one-character gap between Node and headless Edge is found and explained before any row is written, never papered over; stop condition 1 of the plan).
   - The static domain-lock block, the vendor block, the three bare engine blocks with their `JSON.parse` line, the CSS and the markup are inside the digest.
2. **One implementation for both sides.** `lib/alds/rules/engine-digest.ts` (new, pure, inside the frozen tree): `ENGINE_DIGEST_ANCHORS` (the three strings above and `</script>`), and `engineDigestInput(html: string): { ok: true; input: string } | { ok: false; reason: string }`, exported through `lib/alds/rules/index.ts` and shipped in bundle 3. Its header says: never change this function; a new method is a new function selected by `selfCheck.engineDigestAlgo`, whose default and only value today is `v1`; an unknown value gives no digest. The editor hashes the input with the bundle's `sha256HexOfString` (`lib/alds/rules/sha256.ts`); the Guardian hashes the same input with `crypto.subtle` as `guardian.ts` already does for objects; one unit vector proves the two agree.
3. **Per editor release, not per course; never taken from a worktree build.** Two courses from one editor give one digest, proven in Node and in every browser the owner exports from before any row (KIVO ADR 0013 Verification 2). The order is fixed: editor upload, reference export from the hosted editor, allowlist row, LMS deploy, re-check of anything exported in between.

### B. The Guardian recomputes the digest (D2, answered yes; the plan's L2)

4. `guardian.ts checkAndRecord`: before `digestObjects`, read the launch file with `readText` as the two manifests are read, locating it by `course_versions.launch_url` with `?` and `#` stripped and `sanitizeStorageKey` applied under the storage prefix, exactly as `lib/courses/direct-upload.ts` builds the key, falling back to the `<url>` of `cmi5.xml`; `digestObjects` reuses those bytes (today it never records what it fetched, so a read after it would find nothing), the 60 MB budget counts them once, and `digestObjects` returns its per-object entries beside the rolled-up digest so section D can check pins and executable objects (over budget there is no list and the gate fails closed). A launch file that is missing, unreadable or over the 16 MB text cap is `check_error` (re-runnable, as the existing text-object rule). Decode, `engineDigestInput`, hash, compare with `manifest.selfCheck.engineDigest`.
5. **The computed digest is the only one the allowlist lookup sees.** `findAllowlistEntry` receives the computed value, never the claim. The run row's `engine_digest` becomes the computed value; `static_report.gate` gains `engineDigestClaimed`, `engineDigestComputed` and `engineDigestAlgo`.
6. **New reason code** `TIER_REASON.engineDigestMismatch = "engine_digest_mismatch"` in `lib/alds/tier.ts`, written when the claim differs from the computed digest, when `engineDigestInput` reports an anchor failure (reason "no digest: <anchor> found N times"), or when `engineDigestAlgo` is unknown. It sits in `decideTier` after `self_check_missing` and before `engine_not_allowlisted`, because with no computed digest the allowlist leg cannot run; the plan's wording that an anchor failure reads `config_not_certified` is replaced by this placement (the architect's decision; `config_not_certified` keeps the config-block checks of section D).

### C. The trusted-engine row and its registrar (ADR 0005 step 4's allowlist; the plan's L4; the recommended mechanism for D3 and D5, which stay open)

7. **The row** (`AllowlistEntry` in `guardian.ts` and the `$comment` of `lib/alds/engine-allowlist.json`), every field required and checked by `isAllowlistEntry`, so a row missing any field never certifies:
   - as today: `engineDigest`, `rulesBundleHash` (a `bundles.json` hash), `certifiedKinds`, `editorVersion` (the `YYYY.MM.DD[.N]` stamp, ADR 0017 step 3's form), `registeredAt`, `reference`;
   - `engineDigestAlgo` (`v1`);
   - `labels: { [label]: { class, xapiKinds: string[], keyRecomputed: boolean } }`, the labels this engine certifies with their class and the xAPI `kind` values they may use; `keyRecomputed` says whether section D item 6 recomputes the key with `keyFromSlide` or compares ids alone;
   - `slideTypes: { [kivoSlideType]: { label: string | null, reports: "answered" | "responded" | "none" } }`, every slide type the row certifies, from the kind cards, never from a manifest's `slideKinds`; a type not in the map fails closed;
   - `certifiedSettings: { resumePrompt: string[], attemptScoring: string[], weightZeroAllowed: boolean, domainLock: boolean, thirdPartyLrs: boolean, bankTypes: string[] }` (ADR 0005 step 5's settings; D7 fixes the first rows to the plain values);
   - `certifiedSettingKeys: string[]`, every `settings` key the row permits, so a new editor setting fails closed without an LMS code change;
   - `runtimeFiles: { [path]: "sha256:<hex>" }` for `vendor/lottie_light.min.js` and `tincan-min.js`;
   - `allowedExecutablePrefixes: string[]` (empty for the first rows: no `games/`, `sims/` or `assets/*.html`);
   - `harnessReport: { summary: string }` from the certification record.
   A row with the same `(engineDigest, rulesBundleHash)` is updated in place, never duplicated (`findAllowlistEntry` uses `find`, so a second row would never be read).
8. **The registrar** `scripts/alds-register-engine.mjs <reference.zip> --record <sidecar.json> --editor-version <stamp> --reference <text> [--exclude-kind k]* [--exclude-slide-type t]* [--allow-prefix p]* [--widen-setting <field>=<value>]*`. It unzips in memory, computes the digest with the bundle's own functions over `index.html`, reads `rulesBundleHash` and the manifest, and refuses when: the bundle hash is not in `bundles.json`; the manifest's stamped digest differs from its own computation; the record is absent; the record reports a failure (`failed` not 0, the card guard not passed, either F1 compare failed; a 2.0-mode compare of `no_baseline` is accepted only while `engine-allowlist.json` has no entry, so the first row can be written). From the record: `certifiedKinds` = `kindsCovered` of the manifest intersected with the record's `browserProvenKinds`, minus the excludes; `slideTypes` from the record's card map minus the excludes and minus any type whose card lacks a passing browser driver (a passing `visit` driver counts for a card that does not report `answered`, so non-question types stay in the map); `certifiedSettings` from a short fixed plain list unless widened on the command line, visible in the pull request; `certifiedSettingKeys` from the record's settings key list; `runtimeFiles` from the zip. The record is the sidecar KIVO ADR 0013 Decision 11's reference-export tool writes: engine sha256, editor sha256, guard pass, failed count, `browserProvenKinds`, the baseline engine digest, both F1 compare results, the editor's settings key list, the slide type map from the cards, the date. One reviewed pull request per row; a one-line summary for the owner (engine, kinds added, slide types added, settings widened, bundle); the staging Worker deploys on merge; Cloud Run is the owner's deploy; production rides the owner's next tag.
9. `tests/unit/alds-guardian.test.ts`'s allowlist case changes from "the shipped file parses and has engines: []" (its label at `tests/unit/alds-guardian.test.ts:258`) to: every entry is valid, keys are unique, every `rulesBundleHash` is registered, and the fixture engine is not listed.

### D. The config check and the slide binding (ADR 0005 step 5 restored as accepted; the plan's L3; `config_not_certified` and `kind_not_certified`)

10. The gate parses the block `id="kivo-course-config"` from the launch file (failure: `config_not_certified: config block missing`), then checks, each a unit case and each failing closed:
    1. `settings.aldsStandardVersion === "2.0"`, `enableXAPI === true`, `cmi5Mode === true`; `testMode` absent; `minifyLmsBuild !== false`; `_previewStartIdx` absent; no third-party LRS field unless the row's `certifiedSettings.thirdPartyLrs`.
    2. Every key of `settings` is in the row's `certifiedSettingKeys`.
    3. Equalities: `settings.lang` = `manifest.language` = the `cmi5.xml` `langstring lang`; the clamped `passingScore` divided by 100 to two decimals (80 when absent, as the editor substitutes) = the `<au masteryScore>`; `settings.courseUlid`, `courseVersion`, `packageBuild` = the manifest's; `settings.xapiActivityId` = `publisherIds.course`, and `publisherIds.au[0]` = that plus `/au/1`.
    4. ADR 0005 step 5's settings against the row: `resumePrompt` in `certifiedSettings.resumePrompt`; `attemptScoring` on the course and on every slide in `certifiedSettings.attemptScoring`; a zero-weight scoreable slide only when `weightZeroAllowed`; `restrictToAllowedDomains` only when `domainLock`; every bank question `type` in `bankTypes`.
    5. `slideKinds` present in the manifest and equal to the set of slide types in the config; every slide type in the row's `slideTypes`. For a type with a non-null `label`: exactly one `questions[]` entry with `slideId === String(slide.id)` (slide ids are numeric in the editor and strings in the manifest), its `authoringKind` equal to the label, its `kind` in `labels[label].xapiKinds` (else `kind_not_certified`). For a null label: no `questions[]` entry names that slide. An assessment slide: exactly one `quizzes[]` entry with its `slideId`, `bankQids` equal to the bank's `qid` values, its draw and pools equal to the configured ones (the assessment's draw and pool field names are taken at L3 from the G2 engine's assessment reader and confirmed with KIVO; bundle 3 does not read them), and every bank question has a `questions[]` entry whose label follows the bank type.
    6. Per `questions[]` entry: the config's `qid`, `revision` and `contentHash` for that slide or bank question equal the entry's (`revision` and `contentHash` are written into the project by K1b, the export's second pass, after bundle 3; at G1 no editor writes them, so this item is exercised only once K1b lands); for a label whose `keyRecomputed` is true, `keyFromSlide(slide)` equals `correct[]` after `canonicalPatternKey`; otherwise the equality of ids alone.
    7. A fill-blanks slide whose accepted combinations (the product of per-blank variant counts after de-duplication) exceed 64 is `config_not_certified` (D12).
    8. Executable objects and pins: each `runtimeFiles` sha256 equals the stored object's; any other stored `.js`, `.mjs`, `.html` or `.htm` object other than `index.html`, outside the row's `allowedExecutablePrefixes`, is `config_not_certified`; a file-viewer slide whose `fileType` is `text/html` or `application/xhtml+xml` is `config_not_certified` unless a prefix allows it.
    9. `selfCheck.kindsCovered` includes every `authoringKind` present; `alds-selfcheck.json` beside the manifest hashes to `selfCheck.reportHash`.
    10. **Identity stability** (the P4 half of BLUEPRINT R11): one read with the service client of the newest earlier `course_versions` row of the same `course_id` whose `alds_manifest` (a 0100 column, written by `alds_set_version_tier` only when U1 passed) is not null; for every `qid` the two manifests share: the same `kind`, the same option oid set, the same canonical key, and the same `contentHash` for the same `(qid, language, revision)`; otherwise `config_not_certified` naming the qid. A read error skips this item and is recorded in `static_report.config`. No new write; no new column.
11. **Final order in `decideTier`:** the first `error` finding; the package type (cmi5 only); `self_check_missing`; `engine_digest_mismatch`; `engine_not_allowlisted`; `kind_not_certified`; `config_not_certified`; the digest budget code; `certified`.

## Consequences

- "Certified" becomes a property the LMS verifies from the stored bytes alone: the engine bytes (A, B), the runtime files and the absence of other executable objects (D 8), and the course data bound to the manifest (D 3 to 6, 10). A hand-made manifest certifies nothing.
- Certifying a new slide type costs one kind card with a browser driver, one hand-started harness and browser run, one reviewed row (C) and a fresh golden export; a label with new behaviour or a new key function costs a bundle bump as well (the plan's three tiers). Old rows and old exports stay certified; uncertified blocks nobody.
- ADR 0005 step 4 is read wider (the whole page minus two ranges), step 5 is built as accepted, step 7's display and step 11's lens texts are deferred, and step 12's golden package is the owner's course: each is a dated note under ADR 0005, not an edit. ADR 0006 steps 7, 12, 13, 14, 15, 17 and 20 take dated notes likewise.
- The rules tree gains two pure files and one table and is re-registered as bundle 3; bundles 1 and 2 stay listed, so nothing is revoked by the bump. KIVO's K4, K1b, K7a, K5, K7b, K8 and the digest proof of K3 unblock when bundle 3 is registered.
- Two lifecycle specs (66, 67), one workflow step and one repository secret; one registrar script; no migration; no new folder.
- The P4 exit stays open past v1.4.0 and is reached on staging only: the first certified package and a nightly in which spec 67 ran and passed. The production release that carries the first row is a later tag than v1.4.0.

## Alternatives considered

- Fingerprint the bare script blocks only: stable but not tamper-evident (the scratch check of 2026-11-05); rejected by the owner's D1 (b).
- Keep the digest as the package's own claim: a hand-written manifest would certify; rejected by the owner's D2.
- Strip the config, licence and lock from the stored A.1 file and hash the rest: terser's names depend on the course text, so no after-the-fact strip gives a stable hash.
- A third removed range for the domain lock: a removed range is unverified code; a static block inside the digest reads the list from the config instead (KIVO ADR 0013 Decision 3).
- Whitespace normalisation to absorb the A.1 one-character gap: hides the cause; the gap is found and explained before any row.
- `config_not_certified` for an anchor failure (the plan's wording): the code sits after the allowlist leg, which cannot run without a digest; `engine_digest_mismatch` with the anchor reason is placed before it instead.
- A database table for the trusted engines: a migration, RLS and a write path for one or two rows a quarter; a reviewed file read by the code and shipped by deploy is enough (D3's recommendation; revisited if production badges lag).
- An `older_bundle` re-check scope now: it writes `pending` over `certified` and nulls `certified_at`, contradicting ADR 0005 step 7's display; deferred until the display is designed.
- Rewriting ADR 0005 steps 4, 5, 7 and 11: accepted records are never rewritten; this record and dated notes carry the readings.
