## Context

- Decisions 0004/6 (per-version restart) and 0004/7 (course default rule) were left open when ADR 0004 was accepted. On 2026-10-17 the owner decided, in their words: "A. Restart one version — allow restarting learners on a specific incorrect version without affecting learners on newer versions: Yes. B. Default language — uploading a package should not automatically change the course's default language; admin must choose the default explicitly: Yes."
- Restart today: both `force_restart` paths (`app/api/courses/[courseId]/packages/[packageId]/versions/route.ts` lines 163–190; `abandonOldAttempts` in `lib/courses/direct-upload.ts`) select every version of the package except the new one and abandon all their in-progress attempts; neither excludes grant retakes, records a reason or writes an audit row; no action exists on an already-uploaded version. D5b (ADR 0004 step 14) cannot run through them without also resetting learners who started on the corrected D5a version.
- Default today: `publishVersion()` (`lib/courses/upload.ts` lines 439–454) sets `course_packages.current_version_id` and then `courses.current_version_id` unconditionally; `uploadCoursePackage` (multipart new course, new slot, replace), `finalizeDirectUpload` and the activate route call it, so the last published slot becomes the course default. Readers of `courses.current_version_id`: the launch page only when the course has no package rows (`launch/page.tsx` line 311); the catalog (`version_id`, `format`, `version_code`, `has_content`, `available`); the Library and learner course pages' "current" display; `validate_existing`; the reports page; `journey-nudges`; the legacy content route; the launch preload of the next course. The launch page never uses it to choose a language: `?lang=`, the saved preference, the single-active-slot rule or the picker do.
- D5a on staging: reported done by the owner on 2026-10-17 (grandfather upload into the Hindi slot of Turning Escalations; the Framework course's two wrong packages deactivated). Its last step, "Make current" on 2e404b48, is not reachable in the Library: `ActivateVersionButton` renders only for versions that are not their package's current, and 2e404b48 already is the Marathi package's current version. The Framework course's `courses.current_version_id` therefore still resolves to 3b005ed1, whose package is hidden (or about to be). No UI action can move a course default between slots today.
- Deferred at the P0 review, not covered by ADR 0003/0004: (C) migration 0070's policy `admins manage package validations` is `for all` on `is_org_admin(organization_id)`, so any org admin can write the 0098 override columns, `verdict`, `report`, `status` or `sha256` through PostgREST with their own JWT; the override route checks `super_owner` in code, but both upload gates and the finalize check accept a `blocked` row whenever `overridden_at` is set. (D) `nextVersionNumber` is max+1 per package and every abort/sweep path deletes the `uploading` row, so the next upload reuses the number and the `storage_prefix`; `content-backup.yml` runs `rclone copy --immutable` into an Object-Locked bucket at 02:30 UTC, before the 03:00 UTC reaper, so objects of an in-flight or abandoned upload can be locked into the copy, and the reused folder then fails the copy every night.

## Decision

### Part 1 — Accepted (owner, 2026-10-17)

#### A. Per-version restart (decision 0004/6; the mechanism of ADR 0004 step 14a)

1. Route `app/api/courses/[courseId]/packages/[packageId]/versions/[versionId]/restart/route.ts`, `POST`, JSON `{ orgSlug, reason, dry_run? }`. Gate `requireOrgAdminApi(orgSlug)` (`lib/auth/api-admin.ts`: super_owner, owner, admin), as the activate route. Tenant guard as the activate route: the course in the caller's organisation and the version row with `course_id = courseId` and `package_id = packageId`, else 404. `reason` is required for a real run (trimmed, 1–500 characters, the bound of the override reason; 400 otherwise); a dry run needs none.
2. Refusals, nothing changed: 409 `version_is_current` when the version is its package's `current_version_id` and the package is active (resetting learners onto the version they are already on corrects nothing; replace the package first); 409 when `upload_status <> 'ready'`. The current version of an inactive package is allowed (the D5b case of 0a005088 on d4f05fac).
3. Selection, service client: `course_attempts` with `course_version_id = versionId and status = 'in_progress'` → attempt ids and user ids. Grant retakes are excluded by attempt id, the shape the launch page uses (lines 636–647): `attempt_requests` with `status = 'approved' and used_attempt_id in (ids)`; a read error other than `42P01` (pre-0083) answers 503 and changes nothing. Completed, passed, failed and abandoned attempts are never selected; the update is conditional on `id in (selected) and course_version_id = versionId and status = 'in_progress'`, so a completion that lands first wins and no other version is ever touched.
4. Response in both modes: `{ dry_run, version_id, attempt_ids, excluded_grant_retake_ids, by_role: { learner, staff } }`, staff meaning the user holds super_owner, admin or data_analyst in the attempt's organisation (the classes of ADR 0003 step 10); never names or emails. The dry run is the owner's per-attempt list (condition a); it writes no row and no audit entry.
5. Real run: the conditional update; `expireLaunchTokens(svc, abandonedIds)` (`lib/attempts/abandon.ts`); `auditLog({ action: "course.version.attempts_restarted", targetType: "course_version", targetId: versionId, metadata: { courseId, packageId, versionNumber, reason, attemptIds, excludedGrantRetakeIds, requestedCount } })` (`lib/auth/require-platform-owner.ts`, `platform_audit_log`). The response adds `restarted`. The learner-facing consequences already exist (ADR 0004 steps 10–11): the "Reset — module updated" pill, no Resume, not in progress on any surface, 410 on runtime writes.
6. Library: `version-actions.tsx` gains `RestartVersionButton` ("Restart learners on this version"), rendered by `library/[courseId]/page.tsx` for `ready` versions that are not their package's current, and for the current version when the package is inactive. Click → dry run → confirm dialog with the counts ("N in-progress attempts: x learners, y staff; z grant retakes excluded") and a required reason field (extend `components/ui/confirm` or a dialog local to the file) → real call → `router.refresh()`. Zero attempts → the dialog says so and offers nothing.
7. The two `force_restart` paths stay as they are. The Replace dialog's force-restart copy (`languages-section.tsx`) gains one sentence: it resets in-progress learners on every earlier version of this language; to reset one version only, use Restart on that version.
8. D5b runs through this route: the dry run on 7ff60dde is the re-read list of ADR 0004 step 12a; on the owner's go, one real call on 7ff60dde, then PATCH `{ is_active: false }` on the Gujarati package and one real call on d4f05fac; the reason names the ledger entry; the executor records every attempt id in `ops/INCIDENT_LEDGER.md` §5 with the date and the go. On production only after v1.3.0, only for versions the P1 audit flags, on a separate go.

#### B. Explicit course default (decision 0004/7)

9. Rule: `courses.current_version_id` is the current version of the course's default slot. `publishVersion()` keeps updating `course_packages.current_version_id`; it updates `courses.current_version_id` only when (i) the course has none or (ii) the course's current default version belongs to the same `package_id` (read the default version's `package_id` first; write with `.eq("current_version_id", previous)` or `.is("current_version_id", null)` so a concurrent publish cannot cross slots). It never moves the default to another slot. Reconciliation of wordings: the owner's decision says "default language"; a replace or Make current inside the default slot changes the version, not the language, and leaving the pointer on a retired version would break the catalog `version_id`, the Library display and `validate_existing`; this is the rule of ADR 0004 decision 7 as the owner accepted it. The function reports whether the course default moved. Call sites keep their signatures: new course → its first version becomes the default; new slot on an existing course → unchanged; replace or Make current in the default slot → follows; in any other slot → unchanged.
10. Set as default: `app/api/courses/[courseId]/packages/[packageId]/default/route.ts`, `POST` `{ orgSlug }`, `requireOrgAdminApi`, tenant guard as the activate route. The package must belong to the course, be active, and its `current_version_id` must be a `ready` version; else 409 with the reason. Writes `courses.current_version_id = package.current_version_id` and `updated_at`; `auditLog({ action: "course.default_slot_set", targetType: "course", targetId: courseId, metadata: { packageId, language, versionId, previousVersionId, previousPackageId } })`. Already the default → 200 `noop`, no audit row.
11. Library: `library/[courseId]/page.tsx` passes the course default to `languages-section.tsx`, which shows a "Default" badge on the slot whose `current_version_id` equals it, a "Set as default" action on every other active slot with a ready current version, and a warning when no active slot holds the default ("The default version belongs to a hidden language — set a default"). The course header prints "Default language: <slot label>"; the Versions list tags the one version that is the course default.
12. Deactivation guard: PATCH `{ is_active: false }` (`packages/[packageId]/route.ts`) answers 409 `default_slot` when the package holds the course default and another active package with a ready current version exists ("set another language as the default first"). When it is the only active slot, deactivation is allowed and the course has no launchable slot until a default is set.
13. Launch page (`launch/page.tsx` line 311): the fallback to `courses.current_version_id` applies only when the course has no package rows at all; when packages exist and none is active, redirect to `/[org]/courses/[courseId]` (the package list the step-9 block already reads provides the distinction). `?lang=`, preference, single-active and picker resolution are unchanged: the default never chooses a language for a learner.
14. Catalog/CRM (`app/api/integrations/catalog/route.ts`): `version_id`, `format`, `version_code`, `has_content` keep reading `courses.current_version_id`, now the default slot's current version; `available` additionally requires that version's package to be active (fail-soft). `docs/CRM_INTEGRATION.md` gains one sentence defining `version_id` so. No contract break; an optional `default_language` field may be added.
15. Attention Center provider `default-slot` in `lib/attention/collect.ts` (no migration): courses whose default is null while an active slot has a ready version; whose default version's package is inactive; whose default version is not its package's current version.
16. The D5a leftover: once B is on staging the owner clicks "Set as default" on the Marathi slot of The A.M.B.A.K. Framework (current version 2e404b48); the executor verifies read-only that `courses.current_version_id = 2e404b48` and that Turning Escalations' default is the corrected Hindi version from D5a, then marks the two `ops/INCIDENT_LEDGER.md` §3 rows closed and adds the §5 action lines. Nothing else is published on either course before that. On production, after v1.3.0 and only for the courses the P1 audit flags (ADR 0007 step 2 wrong-default check, unchanged), the D5a sequence of ADR 0004 step 13 changes order because B no longer moves the default and step 12 refuses to hide the default slot while another is active: Framework-class course → "Set as default" on the correct slot first, then deactivate the wrong packages; Turning Escalations-class course → replace the Hindi slot (grandfather), then "Set as default" on it.
17. Tests. A — this record amends the placement in ADR 0004 step 17: the restart cases go in `tests/bot/lifecycle/34-version-modes.spec.ts`, which already seeds an in-progress attempt per version: v1 and v2 with in-progress attempts, restart v1 → only v1's attempt abandoned, v2's untouched, audit row with reason and ids; the token case needs a cmi5 attempt (spec 34 seeds SCORM attempts, which mint no `cmi5_launch_tokens` row): seed a token row for the v1 attempt, or use the cmi5 fixture of spec 48, and assert `expires_at <= now()` after the run; dry run → same ids, nothing changed, no audit row; a grant retake on v1 (seeded approved `attempt_requests` row with `used_attempt_id`) stays in progress; a completed attempt on v1 untouched; current version of an active package → 409; current version of a deactivated package → allowed; another organisation's admin → 404; a `user` → 403; empty reason → 400; after the run the reset attempt is not in progress on the learner course page (pill, no Resume), the Library summary, `/api/integrations/progress` and the Report Card path (ADR 0004 step 11; the owner's Approval 2), and a runtime write answers 410. #### D. Content backup versus reused version folders (decision 3)

22. Root fix, code only, no migration (D1): a version number is never reused. `abortDirectUpload`, `sweepAbandonedUploads`, `removeRefusedUpload` and the multipart error path of `uploadCoursePackage` delete the prefix's objects and set `upload_status = 'failed'` (0077's constraint allows it; its column comment already reads "failed = abandoned or failed finalise") instead of deleting the row. `nextVersionNumber` (max+1 over all rows) moves on, and the 0098 unique `storage_prefix` index makes reuse impossible by any path. The course-delete branch of `removeRefusedUpload` (a course created by the same upload) must count versions excluding this `failed` row, otherwise the retained row keeps the orphan course alive; the course delete cascades the failed row (no attempts, so the 0098 guard allows it). The Library hides `failed` rows behind a "show failed uploads" toggle and stops offering Discard on them (`DiscardUploadButton` renders for `failed` today); the content route, the `unpublished-versions` provider and the delete-attempt counts already ignore non-ready rows. Reference codes gain gaps (V03 failed, V04 ready), which is acceptable.
23. Workflow (D2): `content-backup.yml` adds `--min-age 1h` so objects still arriving tonight are copied tomorrow and keeps `--immutable` (the conflict is also the one signal that a ready version's bytes changed, the step-0 incident class). The executor confirms how rclone decides "modified" between the Supabase S3 source and B2: by default size and modtime, and an S3 source without stored mtime reports LastModified, so a browser PUT retry of identical bytes could raise a false conflict; if so, add `--checksum` (or `--size-only`) after checking that both endpoints return comparable hashes. The copy step writes every "immutable file modified" key to the job summary so the owner can tell pre-D1 folder reuse from a changed ready version (ledger entry).
24. Pre-existing conflicts (D3): if the copy already holds objects of a since-reused folder when D ships, Object Lock forbids removing them; the executor lists the keys and the owner chooses between `--exclude` lines for those folders in the workflow (recommended; they hold no learner content) and a fresh destination prefix.
25. Tests: `44-direct-upload.spec.ts` (`DIRECT_UPLOAD_E2E=1`) — abort v2 → row `failed`, prefix empty, the next upload is v3 under a new prefix (its version-number assertions are reviewed); a multipart upload failing mid-way → `failed` row, the next upload moves on; reaper sweep → `failed`, not deleted; the Library hides failed rows. Workflow: a `workflow_dispatch` input `dry_run` running `rclone copy --dry-run` is the rehearsal; the next scheduled run's summary shows zero conflicts.

### Risks and protections

| Risk | Protection |
|---|---|
| Learners: a restart closes attempts with real progress | one version, in-progress only, grant retakes excluded; the dry run shows the list first; condition (a): the owner's go before any D5b run; the reset is honest on every surface (ADR 0004 steps 10–11) |
| Grading: an abandoned attempt is counted, or a completion is lost | abandoned is never official nor in progress (ADR 0004 step 11); the conditional update lets a concurrent completion win; completed, passed and failed rows are never selected |
| Privacy: the per-attempt list leaks identities | ids and role classes only, in the route response, the audit metadata and the ledger |
| Existing records: a course default moves unexpectedly or points at hidden content | the same-slot rule (step 9), the deactivation guard (12), the launch redirect (13), the Attention provider (15), the P1 audit check |
| A reset learner's open tab keeps writing | tokens expired at restart; runtime writes answer 410 |
| C: uploads break on the policy flip | code first, migration after; never in the pre-tag sitting |
| D: a `failed` row is served or restarted | the content route refuses non-ready rows; restart refuses them (step 2) |

## Consequences

- D5b has a tool that touches one version and records why; the two force-restart paths remain for whole-package resets.
- A course default is a deliberate slot choice; uploads and rollbacks move only the version within that slot. The Framework leftover closes with one click once B is on staging.
- CRM `version_id` is stable across uploads to non-default slots.
- If C is accepted, `package_validations` is read-only for every PostgREST role except `service_role`, and the later migration numbers shift by one.
- If D is accepted, version numbers may have gaps, `failed` rows persist as history, and the nightly copy stays meaningful as an integrity signal.

## Alternatives considered

- A: re-running replace-package with `force_restart` (rejected in ADR 0004 step 14a); SQL on attempts (never, ADR 0002 decision 4); a `restart_reason` column on `course_attempts` (a migration for what the audit row holds; revisit with 0099 if the learner note should show the reason); a super_owner-only gate (admins already run force-restart; the reason and the audit row are the control; the owner may tighten).
- B: a `courses.default_package_id` column (a cleaner model, but a migration and ten readers to change; the implicit rule needs none); auto-adopting another slot when the default's slot is deactivated (the automatic behaviour the owner removed); deriving the default from the NULL-language legacy package (not every course has one).
- C: a trigger preserving the protected columns on non-service writes (order-independent, but forged inserts stay possible and the policy still reads "manage"); a GUC-gated writer function as ADR 0005 step 2 (heavier than needed when every write is already behind a route).
- D: excluding non-ready prefixes by reading the database from the workflow (couples the backup to the database); a dated destination per night (duplicates the estate); dropping `--immutable` (loses the integrity signal).
